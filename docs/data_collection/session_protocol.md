# Live Session Protocol
> **Historical protocol:** Participant collection closed after the ninth retained formal session on 10 August 2026. The procedure below records how the retained sessions were governed by Ethics Pack Version 4.4 and their manifest-recorded collection profiles. It must not be used to start a new pilot or participant session. Non-research dry runs for later system development remain separate from participant collection.

1. It must be confirmed that site permission remains valid
2. It must be confirmed that the participant-facing Ethics Pack Version 4.4 PDF has been generated and visually verified
3. It must be confirmed that every participating Counter Agent has received Version 4.4 and completed the required acknowledgement
4. It must be confirmed that Station Managers and all other non-participants will remain outside the retained Zone A camera region
5. Pseudonymised participant IDs must be assigned
6. The camera view, mask and sensor placement must be shown to each participant
7. The manual items must be completed in the pre-session checklist
8. After the activation gate is complete, start the formal runner with the approved `config/collection.zone_a.v7.yaml`. Confirm its pinned SHA-256 and all hashed camera, mask, placement, firmware, model, tracker, schema and procedure artifacts pass before preflight
9. The fail-closed Phase 7.2 preflight must be run and the session must be prepared. The presence of a validated `planned` manifest with an SGT session identifier must be confirmed before any writer is started.
10. All writers must be started only through the manifest-backed writer-start gate. It must be confirmed that the manifest is atomically marked `running` before ordinary duties are observed. The shared pause/stop controller must be obeyed by each writer, and final file/count/gap accounting must be provided. Only the localhost masked track-ID preview printed by that same runner must be opened and kept open throughout the retained session; an alignment preview or second tracking process must not be substituted. Under the historical pilot and participant procedure, the participant pseudonym, current local track ID and dominant approved activity were required to be selected using the annotation controls on that page. Transitions are timestamped and aligned automatically by the local server; the clock must not be transcribed manually. On the desktop, the masked display and annotation tools are retained on the left, while the independently scrolling participant-card grid is positioned at the top right. Manual track drafts, keyboard focus and selected activities must be kept visible across ordinary status polls. A fail-closed replacement-track prompt is retained for a complete-window track loss, and annotation is not silently resumed. Under the historical procedure, `Add consenting participant` was required when an additional consenting Counter Agent arrived; the assigned pseudonym had to be entered and consent explicitly confirmed. The new card and manifest audit entry must be verified before annotation is started. This control must never be used for a non-participant or unconfirmed consent.
11. The start time and session identifier must be recorded
12. Call Phase 7.3 lifecycle `pause()` immediately for camera movement, mask failure, stream/node/storage/equipment failure, privacy-boundary failure or entry by anyone outside the approved participant scope.
13. Every affected multimodal-window ID must be linked to the open incident using `exclude_windows()`. Those windows must be treated as unusable for modelling.
14. The required isolation/deletion and recovery actions must be completed. `resume()` may be called only after recovery is verified; resumption from privacy-critical incidents is prohibited while required deletion is incomplete.
15. End a participant's active annotation when that participant leaves. Any remaining active annotations close automatically when the session is stopped cleanly.
16. The session must be stopped after no more than 90 minutes through the lifecycle `stop()` method. Application writers must not be closed independently.
17. It must be confirmed that every writer closed and reported its relative local file, observed, written and excluded record counts, gap count and longest gap.
18. It must be confirmed that `completed` is recorded in the atomically written final manifest. An `aborted` result must be treated as unusable until reviewed
19. The post-session checklist must be completed
20. Transfer any permitted temporary masked video to the approved local storage location and follow the approved deletion schedule.
